     1→     1→// ============================================================================
     2→     2→// File: prisma/schema.prisma
     3→     3→// Purpose: Central database schema for PMS — Pradeep Medical Store.
     4→     4→//          Online pharmacy platform with customer storefront + admin panel.
     5→     5→// Database: PostgreSQL 15+ — hosted on Supabase (managed).
     6→     6→// ORM:      Prisma 6.x
     7→     7→//
     8→     8→// Design principles:
     9→     9→//   1. Normalized — no duplicate data storage (product images live ONLY in
    10→    10→//      ProductImage, not duplicated across Product columns).
    11→    11→//   2. Indexed — every foreign key and frequently-filtered column has an index.
    12→    12→//   3. Typed — monetary values use Decimal(10,2) for exact precision; long
    13→    13→//      text fields use @db.Text to leverage PostgreSQL's native text type.
    14→    14→//   4. Cascading — child records (OrderItem, CartItem, etc.) are deleted when
    15→    15→//      their parent is deleted, preventing orphan rows.
    16→    16→//
    17→    17→// Connection notes (Supabase):
    18→    18→//   - DATABASE_URL uses the Supavisor transaction-mode pooler (port 6543) with
    19→    19→//     ?pgbouncer=true for efficient connection reuse in serverless (Vercel).
    20→    20→//   - DIRECT_URL uses the session-mode pooler (port 5432) for migrations.
    21→    21→//   - FK constraints are enforced at the PostgreSQL level (relationMode left at
    22→    22→//     default) — Supabase Supavisor supports prepared statements in transaction
    23→    23→//     mode, so no ORM-level emulation is required.
    24→    24→// ============================================================================

    34→    34→}

   907→   907→/// Per-customer, per-device registration record for the onboarding wizard.
   908→   908→/// One customer can have multiple device registrations (Chrome Desktop,
   909→   909→/// Chrome Android, PWA install, etc.). Each browser/device is identified by
   910→   910→/// a locally-generated `deviceId` (UUID stored in localStorage) so the
   911→   911→/// onboarding wizard only shows ONCE per device.
   912→   912→///
   913→   913→/// Lifecycle:
   914→   914→///   • Row created when the wizard first appears (status=pending).
   915→   915→///   • status=skipped  → customer clicked "Skip for Now".
   916→   916→///   • status=completed→ customer finished the wizard + test push verified.
   917→   917→///
